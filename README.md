# vc-gshtools: Vibe-Coded Geodetic Spherical Harmonic Tools

vc-gshtools is a C++20 library for spherical-harmonic synthesis of ultra-high-degree gravity-field models
(degree and order 2190 and above). It uses SIMD kernels (AVX2 and AVX-512) and OpenMP, and includes three
Legendre-function recurrences: SFC, MSFC and ERA. It also contains supporting utilities: a coefficient model
reader, ellipsoid and normal-gravity definitions, geodetic and Cartesian coordinate conversion, tide-system
conversions and a delimited-table reader.

"Vibe-coded" is part of the name on purpose: the code was written with an AI coding assistant. See
[Provenance](#provenance) below.

## Status and scope

Public now:

- `src/cpp/gsh_utils`, `src/cpp/gsh_legendre` and `src/cpp/gsh_expansion`: the library target `gsh`.
- The unit tests of these modules (`tests/`, GoogleTest).
- Documentation of these modules in [docs/README.md](docs/README.md).
- The point example `examples/ex_puntual.cpp`.
- The spherical-harmonic synthesis benchmark in [benchmark/shs](benchmark/shs), with its drivers, data
  description, raw results and summary.

Future work, not in this repository yet: geoid computation, residual terrain reduction (RCR), least-squares
collocation (LSC). Nothing about their internals is published here.

## Quick start (Windows 11, x64)

The script [config/config.ps1](config/config.ps1) does everything needed to build the project from scratch:
it checks the tools, bootstraps vcpkg if it is missing, configures, builds and runs the tests.

```powershell
# From the repository root, in PowerShell 7 or Windows PowerShell 5.1.
.\config\config.ps1 -DryRun                      # shows what would be done; changes nothing
.\config\config.ps1 -Preset clang -InstallPrereqs # installs missing tools with winget (asks first)
```

Without `-InstallPrereqs` the script installs nothing and prints the winget commands for anything missing.
`-InstallPrereqs` can require administrator rights (winget asks through UAC). The Visual Studio Build Tools
download is several gigabytes. The first configure builds FFTW, Eigen and GoogleTest through vcpkg, which takes a
long time and needs internet access. Run `.\config\config.ps1 -Preset msvc` to use `cl.exe` instead of
`clang-cl`. Run it with `-Clean` to delete the build folder of the preset first.

Compilers are `cl.exe` (preset `msvc`) and `clang-cl.exe` (preset `clang`). The presets are in
[CMakePresets.json](CMakePresets.json); they need `VCPKG_ROOT` to point at a vcpkg checkout.

## Building and testing by hand

```powershell
cmake --preset clang
cmake --build --preset clang
ctest --preset clang
```

Build products go to `build\<preset>\bin`. The tests that need external model or grid files (EGM2008,
XGM2019e, the Colorado grid) skip themselves when those files are absent. The public tree does not contain them.

## Benchmark

[benchmark/shs](benchmark/shs) compares the synthesis of this library with GrafLab (accuracy reference), pyharm
(a Python wrapper of CHarm) and pyshtools (SHTOOLS), on the XGM2019e model and 509 points in Colorado.
Start with [benchmark/shs/results/Summary.md](benchmark/shs/results/Summary.md). Model provenance and the
decompression step are in [benchmark/shs/data/DATA.md](benchmark/shs/data/DATA.md). The compressed model is
`XGM2019e_2190_tide_free.gfc.xz`, an asset of the Release `data-v1` (not in the git tree); download it into
`benchmark/shs/data/` and decompress it before running the drivers. The benchmark
needs third-party tools that this repository does not distribute (see [NOTICE](NOTICE)).

## Validation

The only validation of numerical results in this repository is the benchmark in `benchmark/shs`. GrafLab is the
accuracy reference. pyharm (CHarm) and pyshtools (SHTOOLS) are efficiency and general references. The unit tests
check the modules against reference values stored in the test files (some were generated by an earlier Python
implementation of the same formulas). They are not a substitute for the benchmark.

## Platform

Windows 11, x64, Visual Studio C++ tools with `cl.exe` or `clang-cl.exe`, CMake 3.25 or later, Ninja, vcpkg.
The SIMD kernels are built with the AVX2 and AVX-512 flags of each compiler. The project has not been tried on
other operating systems or compilers.
